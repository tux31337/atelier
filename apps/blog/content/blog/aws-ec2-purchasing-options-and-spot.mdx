EC2 비용 최적화 문제는 대부분 "어떤 구매 옵션이 이 상황에 맞는가"로 나온다.
인스턴스 타입을 고르는 문제가 CPU, 메모리, 스토리지 병목을 보는 문제라면, 구매 옵션 문제는 비용, 약정, 유연성, 중단 가능성을 비교하는 문제다.

EC2 생성과 인스턴스 타입 기초는 [EC2 기초 글](/blog/aws-ec2-first-website)에서 다룬다.
이 글은 구매 방식과 Spot 계열만 따로 분리해 정리한다.

## On-Demand는 기본값이다

On-Demand는 사용한 만큼 지불하는 기본 구매 방식이다.
선결제도 없고 장기 약정도 없다.
대신 같은 사용량이라면 할인 옵션보다 비용이 높은 편이다.

다음 상황에 적합하다.

- 짧게 실행하는 워크로드
- 사용량을 예측하기 어려운 워크로드
- 갑자기 트래픽이 늘 수 있는 신규 서비스
- 중단되면 안 되는 작업

시험에서 "약정 없이 바로 시작해야 한다", "사용량을 예측하기 어렵다", "중단되면 안 된다"는 조건이 있으면 On-Demand를 먼저 떠올린다.

## Reserved Instance는 일정 사용량 할인이다

Reserved Instance는 1년 또는 3년 약정으로 할인을 받는 방식이다.
인스턴스 타입, 리전, 테넌시, 운영 체제 같은 속성에 맞춰 할인 혜택이 적용된다.

장기간 일정하게 켜져 있는 서버나 데이터베이스처럼 사용량이 안정적인 워크로드에 적합하다.

Reserved Instance는 크게 두 종류로 구분한다.

- **Standard RI**: 할인 폭이 크지만 변경 유연성이 낮다.
- **Convertible RI**: 할인 폭은 낮지만 인스턴스 패밀리, 운영 체제, 테넌시 같은 속성을 바꿀 수 있다.

시험에서는 "가장 큰 할인"이면 Standard RI, "약정은 하되 인스턴스 계열 변경 가능성이 있다"면 Convertible RI로 구분한다.

## Savings Plans는 사용 금액 약정이다

Savings Plans는 특정 인스턴스 하나를 예약하는 것이 아니라, 1년 또는 3년 동안 시간당 특정 금액 사용을 약정하는 방식이다.
약정한 사용량 안에서는 할인된 가격이 적용되고, 초과 사용량은 On-Demand 요금으로 청구된다.

Reserved Instance보다 유연한 비용 절감 방식으로 자주 나온다.
특히 Compute Savings Plans는 EC2뿐 아니라 Fargate, Lambda 사용량에도 적용될 수 있어, 워크로드가 여러 컴퓨팅 서비스로 움직일 가능성이 있을 때 유리하다.

문제에서 "장기 약정으로 비용을 낮추고 싶지만 인스턴스 패밀리나 리전 변경 가능성이 있다"는 뉘앙스가 있으면 Savings Plans를 검토한다.

## Dedicated Host는 물리 서버 제어가 핵심이다

Dedicated Host는 물리 서버 전체를 전용으로 사용하는 방식이다.
소켓, 코어, VM 단위 라이선스가 필요한 BYOL 환경이나 규정 준수 요구사항이 있을 때 사용한다.

핵심은 **물리 서버 수준의 가시성과 제어**다.
어떤 물리 호스트에 인스턴스가 올라가는지 제어해야 하는 라이선스나 감사 요구사항이 있으면 Dedicated Host가 강한 후보가 된다.

Dedicated Instance도 전용 하드웨어에서 실행되지만, Dedicated Host처럼 물리 서버 자체에 대한 세밀한 제어권을 제공하지는 않는다.

## Capacity Reservation은 할인보다 용량 보장이다

Capacity Reservation은 특정 Availability Zone에 On-Demand 용량을 예약하는 기능이다.
할인을 받기 위한 기능이 아니라, 필요할 때 인스턴스를 시작할 수 있도록 용량을 확보하는 기능이다.

중요한 점은 인스턴스를 실제로 실행하지 않아도 예약한 용량에 대해 요금이 청구될 수 있다는 것이다.
비용 할인까지 원하면 Reserved Instance나 Savings Plans와 함께 고려해야 한다.

```text
할인 목적 -> RI 또는 Savings Plans
특정 AZ 용량 보장 -> Capacity Reservation
```

시험에서 "장애 복구 시 특정 AZ에서 반드시 용량을 확보해야 한다"처럼 용량 보장이 핵심이면 Capacity Reservation을 고른다.

## Spot Instance는 싸지만 중단될 수 있다

Spot Instance는 AWS의 남는 EC2 용량을 할인받아 사용하는 방식이다.
AWS 공식 설명 기준으로 On-Demand 대비 최대 90%까지 비용을 줄일 수 있지만, AWS가 용량을 회수하면 인스턴스가 중단될 수 있다.

Spot은 다음 워크로드에 적합하다.

- 배치 처리
- 데이터 분석
- 이미지 렌더링과 미디어 처리
- 컨테이너 워크로드
- CI/CD 작업
- HPC와 대규모 분산 처리
- 중단을 견딜 수 있는 stateless 또는 fault-tolerant 워크로드

반대로 중요한 데이터베이스, 단일 인스턴스에 상태가 강하게 묶인 서비스, 중단되면 안 되는 핵심 업무에는 적합하지 않다.

Spot Instance가 중단될 때는 보통 2분 전 interruption notice가 제공된다.
다만 hibernate 동작은 즉시 시작될 수 있으므로 2분 동안 정리할 수 있다고 단순화하면 안 된다.
애플리케이션은 작업 상태를 저장하거나 큐에 작업을 되돌리는 식으로 중단을 견뎌야 한다.

## Spot Request는 요청 객체다

Spot Request는 원하는 Spot Instance 조건을 AWS에 요청하는 객체다.
요청에는 원하는 인스턴스 수, AMI, 인스턴스 타입, 키 페어, 요청 유효 기간 같은 정보가 들어간다.

Spot Request 유형은 다음처럼 구분한다.

- **One-time request**: 요청이 충족되어 인스턴스가 시작되면 목적을 달성한다.
- **Persistent request**: 요청이 만료되거나 취소될 때까지 유지되며, 인스턴스가 중단되면 조건이 맞을 때 새 인스턴스를 다시 시작할 수 있다.

시험에서 자주 나오는 정리 순서는 다음과 같다.

```text
Spot을 완전히 종료하려면
1. Spot Request를 먼저 취소한다.
2. 연결된 Spot Instance를 종료한다.
```

Persistent request가 살아 있는 상태에서 인스턴스만 종료하면, AWS가 조건을 맞춰 새 Spot Instance를 다시 만들 수 있다.

## Spot Fleet과 EC2 Fleet은 여러 풀을 사용한다

Spot Fleet 또는 EC2 Fleet은 여러 인스턴스 타입과 여러 Availability Zone을 후보로 두고 목표 용량을 맞추는 방식이다.
하나의 인스턴스 타입과 하나의 AZ만 고르는 것보다 Spot 용량을 확보할 가능성이 높아진다.

Fleet에서는 여러 launch pool을 정의할 수 있다.
각 풀은 인스턴스 타입, AZ, AMI 같은 조건 조합으로 볼 수 있다.
목표 용량은 인스턴스 수, vCPU, 메모리 기준으로 지정할 수 있다.

할당 전략은 문제 문맥에 맞춰 고른다.

- **price-capacity-optimized**: 용량이 충분한 풀 중 가격이 낮은 풀을 선택한다. 대부분의 Spot 워크로드에 권장되는 기본 후보로 본다.
- **capacity-optimized**: 중단 위험을 줄이기 위해 사용 가능한 용량이 큰 풀을 우선한다.
- **diversified**: 여러 풀에 분산해 특정 풀 중단의 영향을 줄인다.
- **lowest-price**: 가장 저렴한 풀을 고른다. 비용은 낮지만 중단 위험이 커질 수 있다.

문제에서 "가장 저렴한 가격"을 직접 묻는지, "중단 위험을 줄이면서 가격도 고려"하는지를 구분해야 한다.

## Spot Block은 활성 기능으로 외우지 않는다

과거에는 정해진 시간 동안 Spot Instance를 실행하는 Spot Block이 있었다.
하지만 Spot Instances with a defined duration, 즉 Spot blocks는 신규 고객에게 2021년 7월 1일부터 제공되지 않았고, 기존 고객 지원도 2022년 12월 31일까지로 공지되었다.

따라서 최신 기준의 SAA 공부에서는 Spot Block을 현재 선택 가능한 구매 옵션처럼 외우지 않는 편이 안전하다.
중단을 견딜 수 있으면 일반 Spot Instance를, 중단되면 안 되면 On-Demand나 다른 약정 옵션을 검토한다.

## 시험 포인트 정리

- 예측 불가, 단기, 중단 불가 워크로드는 On-Demand가 기본 후보다.
- 장기 일정 사용량은 Reserved Instance 또는 Savings Plans로 할인받는다.
- 유연한 약정 할인은 Savings Plans 또는 Convertible RI를 검토한다.
- BYOL, 물리 서버 제어, 규정 준수 요구는 Dedicated Host를 본다.
- 특정 AZ 용량 보장이 목적이면 Capacity Reservation을 본다.
- Spot은 저렴하지만 AWS가 용량을 회수하면 중단될 수 있다.
- Persistent Spot Request는 먼저 취소한 뒤 인스턴스를 종료해야 다시 생성되지 않는다.
- Spot Fleet은 여러 인스턴스 타입과 AZ를 후보로 두고 목표 용량을 맞춘다.
