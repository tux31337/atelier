IAM의 마지막 구성 요소는 **IAM Role(역할)** 이다.  
지금까지 본 사용자·그룹·정책이 사람을 위한 것이었다면, Role은 **AWS 서비스**를 위한 것이다. 개념을 보고 콘솔에서 직접 만들어 본다.

## IAM Role이란

일부 AWS 서비스는 우리 계정 안에서 어떤 작업을 수행해야 한다. 사람과 마찬가지로 서비스도 그러려면 **권한**이 필요하다. 그래서 **AWS 서비스에 권한을 부여**하기 위해 IAM Role을 만든다.

Role은 사용자와 같지만, **실제 사람이 아니라 AWS 서비스가 사용하도록** 만들어졌다는 점이 다르다.

## 왜 필요한가 (EC2 예시)

예를 들어 **EC2 인스턴스**(가상 서버, 다음 섹션에서 다룸)가 AWS에서 어떤 작업을 하려 한다고 하자. 그러려면 EC2 인스턴스에 권한을 줘야 한다. 이때 IAM Role을 만들어 인스턴스에 부여한다.

```text
EC2 인스턴스(가상 서버)
  -> AWS의 어떤 정보·작업에 접근하려 함
  -> IAM Role을 부여받음
  -> 작업 시 Role을 사용해 권한 범위 안에서 API 호출
```

Role에 권한을 올바르게 부여했다면, 인스턴스는 하려던 호출에 정상적으로 접근할 수 있다.

## 일반적인 Role 예시

대표적인 Role은 다음과 같다.

```text
EC2 인스턴스 역할      -> EC2 인스턴스가 AWS 작업을 수행할 때
Lambda 함수 역할       -> Lambda 함수가 AWS 작업을 수행할 때
CloudFormation 역할    -> CloudFormation이 AWS 작업을 수행할 때
```

## 역할 생성 실습

왼쪽에서 **역할(Roles)** 을 누르면 계정에 이미 만들어진 역할이 몇 개 보인다(개수는 중요하지 않다). 여기서 **새 역할**을 만든다.

먼저 **신뢰할 수 있는 엔티티 유형**을 고른다. 다섯 가지 정도가 있지만, 실습과 시험에서 알아야 할 것은 **AWS 서비스**다. 이것을 선택하고, 서비스로 **EC2**를 고른다(사용 사례도 EC2). 그다음 EC2 인스턴스가 IAM의 내용을 읽을 수 있도록 **IAMReadOnlyAccess** 정책을 연결하고, 역할 이름(예: `DemoRoleForEC2`)을 지정해 생성한다.

```text
역할(Roles) > 역할 만들기
1) 신뢰할 수 있는 엔티티 유형 -> AWS 서비스
2) 서비스 / 사용 사례         -> EC2
3) 권한(정책) 연결           -> IAMReadOnlyAccess
4) 역할 이름                 -> DemoRoleForEC2
5) 검토 후 생성
```

검토 화면에서 **신뢰할 수 있는 엔티티**가 EC2로 잡혀 있는데, 이는 **EC2 서비스가 이 역할을 맡을(assume) 수 있다**는 의미다. 생성하면 역할 목록에 나타나고, 연결된 권한을 확인할 수 있다. 이 역할은 **EC2 섹션에서 실제로 사용**하므로 지금은 만들어 두기만 한다.

## 정리

```text
IAM Role
  -> AWS 서비스에 권한을 주기 위한 개체 (사람이 아니라 서비스가 사용)
  -> 예: EC2 인스턴스에 Role 부여 -> Role로 권한 범위 내 API 호출
  -> 일반적인 Role: EC2 인스턴스 / Lambda 함수 / CloudFormation

생성 실습
  -> 신뢰할 수 있는 엔티티 = AWS 서비스(EC2) = 그 서비스가 역할을 맡을 수 있다는 신뢰 관계
  -> 권한 = IAMReadOnlyAccess, 이름 = DemoRoleForEC2
  -> 생성 후 목록에서 확인, EC2 섹션에서 사용 예정
```
