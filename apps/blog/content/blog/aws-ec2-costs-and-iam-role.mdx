EC2를 처음 만들 때는 인스턴스 생성 화면과 웹 서버 실행에 집중하기 쉽다.
하지만 SAA 시험과 실제 실습에서는 **비용이 어디서 생기는지**와 **EC2가 AWS API를 호출할 때 어떤 권한 방식을 써야 하는지**를 함께 봐야 한다.

인스턴스 생성 흐름과 User Data는 [EC2 기초 글](/blog/aws-ec2-first-website)에서, 포트와 timeout 문제는 [EC2 보안 그룹 글](/blog/aws-ec2-security-groups)에서 자세히 다룬다.
이 글은 EC2 주변의 비용 관리와 IAM Role만 분리해서 정리한다.

## 실습 전에는 Billing부터 확인한다

AWS 실습 계정에서는 먼저 Billing and Cost Management 콘솔을 확인한다.
현재 비용, 예상 비용, 지난달 비용을 보고, 비용이 발생했다면 `Bills` 메뉴에서 어떤 서비스와 리전이 비용을 만들었는지 확인한다.

비용 화면에서 `Charges by service`를 펼치면 EC2, VPC, EBS, NAT Gateway, Load Balancer처럼 서비스별 비용을 나눠 볼 수 있다.
EC2 인스턴스를 하나만 만들었다고 해도 Public IPv4 주소, EBS 볼륨, Elastic IP 같은 주변 리소스가 별도 비용을 만들 수 있다.

IAM 사용자로 Billing 페이지에 접근했을 때 권한이 거부될 수 있다.
관리자 정책이 붙어 있어도 Billing 접근은 계정 설정에서 별도로 막혀 있을 수 있기 때문이다.
이 경우 루트 계정으로 로그인해 Account 설정에서 **IAM user and role access to Billing information**을 활성화해야 IAM 사용자나 역할이 비용 정보를 볼 수 있다.

## Budget은 비용 알림 장치다

Budget은 비용이 예상보다 커질 때 알림을 받기 위한 장치다.
시험에서 Budget 생성 절차를 세세하게 외울 필요는 적지만, 비용 초과를 사전에 감지하는 서비스라는 점은 알아야 한다.

실습 계정에서는 보통 다음 두 가지를 둔다.

- **No-spend budget**: 0.01달러처럼 아주 작은 비용이 발생해도 알림을 받는다.
- **Monthly cost budget**: 예를 들어 월 10달러를 기준으로 실제 비용 85%, 실제 비용 100%, 예상 비용 100% 도달 시 알림을 받는다.

Budget은 비용 발생을 막지는 않는다.
리소스를 계속 실행하면 비용은 계속 발생하고, Budget은 그 사실을 이메일이나 알림으로 알려 주는 역할을 한다.

## Free Tier는 모든 비용을 없애 주지 않는다

EC2 Free Tier가 있다고 해서 AWS 계정의 모든 비용이 0원이 되는 것은 아니다.
무료 범위는 서비스, 사용량, 계정 생성 시점, 리전에 따라 달라질 수 있고, Free Tier 밖의 리소스는 바로 과금될 수 있다.

EC2 실습에서 특히 확인할 항목은 다음과 같다.

- 실행 중인 EC2 인스턴스 시간
- 루트 EBS 볼륨과 추가 EBS 볼륨
- Public IPv4 주소와 Elastic IP
- Load Balancer와 NAT Gateway
- 스냅샷, AMI, 남겨 둔 테스트 리소스

인스턴스를 `Stop`하면 컴퓨팅 요금은 멈추지만, EBS 볼륨이나 Public IPv4 주소처럼 남아 있는 리소스 비용은 계속 발생할 수 있다.
인스턴스를 `Terminate`하면 인스턴스는 삭제되지만, 루트 볼륨의 `Delete on termination` 설정과 별도 리소스 정리 여부를 함께 확인해야 한다.

## Public IPv4 비용을 따로 본다

EC2를 기본 VPC에 만들면 인터넷 접속을 위해 Public IPv4 주소가 자동으로 붙는 경우가 많다.
이 주소는 웹 브라우저에서 `http://<공용 IPv4 주소>`로 접속할 때 쓰는 주소다.

2024년 2월 1일부터 AWS는 Public IPv4 주소에 시간당 요금을 부과한다.
Amazon VPC Pricing 기준으로 in-use Public IPv4와 idle Public IPv4 모두 시간당 0.005달러 과금 항목이다.
EC2 Free Tier 고객에게는 EC2 Public IPv4 사용량 일부가 제공될 수 있지만, Free Tier 조건 밖의 사용량이나 다른 서비스의 Public IPv4까지 모두 무료라고 가정하면 안 된다.

Public IPv4 비용은 EC2만의 문제가 아니다.
퍼블릭 Load Balancer, public RDS, NAT Gateway, Global Accelerator처럼 Public IPv4를 쓰는 리소스도 비용을 만들 수 있다.

<Callout title="인스턴스만 지워도 비용이 남을 수 있다">
실습 후에는 EC2 인스턴스 목록만 보지 말고 VPC, EBS, Elastic IP, Load Balancer, NAT Gateway, 스냅샷도 함께 확인한다.
</Callout>

Public IPv4 사용량을 추적할 때는 Billing의 `Bills`와 Cost Explorer를 먼저 확인한다.
더 자세한 IP 사용 현황은 VPC IPAM의 Public IP Insights에서 확인할 수 있다.

## EC2에서 AWS API를 호출할 때는 IAM Role을 쓴다

EC2 인스턴스 안에서 AWS CLI나 애플리케이션이 AWS API를 호출해야 할 수 있다.
예를 들어 인스턴스에서 S3 객체를 읽거나, CloudWatch에 로그를 쓰거나, IAM 정보를 조회하는 경우가 있다.

이때 `aws configure`로 access key와 secret access key를 인스턴스 안에 직접 저장하는 방식은 피해야 한다.
장기 자격 증명이 파일로 남으면, 그 인스턴스에 접근한 사람이 키를 가져가 다른 곳에서 사용할 수 있기 때문이다.

올바른 방식은 EC2 인스턴스에 IAM Role을 연결하는 것이다.
EC2는 Instance Profile을 통해 IAM Role을 사용하고, 인스턴스 안의 AWS SDK나 AWS CLI는 Instance Metadata Service에서 임시 자격 증명을 받아 API를 호출한다.

```text
EC2 애플리케이션이 AWS API 호출 필요
  -> access key 저장 금지
  -> EC2 IAM Role 연결
  -> 임시 자격 증명으로 호출
```

IAM Role은 인스턴스 생성 시 선택할 수 있고, 실행 중인 인스턴스에서도 `Actions > Security > Modify IAM role` 흐름으로 바꿀 수 있다.
하나의 EC2 인스턴스에는 한 번에 하나의 IAM Role만 연결할 수 있지만, 같은 역할은 여러 인스턴스에 재사용할 수 있다.

<Callout title="시험에서 가장 중요한 문장">
EC2 인스턴스가 AWS 서비스에 접근해야 하면 access key를 저장하지 말고 IAM Role을 연결한다.
</Callout>

## 권한 문제는 AccessDenied로 드러난다

보안 그룹 문제는 보통 timeout으로 드러난다.
반면 EC2 안에서 AWS CLI를 실행했는데 권한이 부족하면 `AccessDenied`가 나온다.

예를 들어 EC2 인스턴스에 IAM 읽기 권한이 없는 역할을 붙인 상태에서 `aws iam list-users`를 실행하면 권한 오류가 난다.
정책을 추가하면 잠시 전파 시간을 거친 뒤 명령이 성공할 수 있다.

이 구분이 중요하다.
브라우저에서 웹 서버가 열리지 않으면 보안 그룹, 라우팅, 애플리케이션 실행 상태를 본다.
AWS API 호출이 실패하면 IAM Role과 정책을 본다.

## 시험 포인트 정리

- Billing의 `Bills`에서 서비스별, 리전별 비용 원인을 확인한다.
- Budget은 비용을 차단하지 않고 비용 발생 또는 예상 초과를 알려 준다.
- Free Tier가 있어도 EBS, Public IPv4, Elastic IP, Load Balancer, NAT Gateway 비용이 남을 수 있다.
- Public IPv4 주소는 in-use와 idle 모두 과금 대상이 될 수 있다.
- EC2가 AWS API를 호출해야 하면 access key를 저장하지 않고 IAM Role을 연결한다.
- EC2 IAM Role은 Instance Profile을 통해 임시 자격 증명을 제공한다.
- timeout은 네트워크나 보안 그룹, `AccessDenied`는 IAM 권한 문제로 먼저 나눠 본다.
