사용자와 그룹을 만들었으니 이제 이들이 손상되지 않도록 보호할 차례다.  
IAM에는 두 가지 방어 메커니즘이 있다. **비밀번호 정책**과 **MFA(다중 인증)** 다. 개념을 먼저 정리하고, 이어서 콘솔에서 직접 설정한다.

## 비밀번호 정책

비밀번호가 강력할수록 계정 보안이 강해진다. 비밀번호 정책은 계정에 대한 **무차별 대입 공격(brute force)** 을 막는 데 도움이 된다.

## MFA란

비밀번호 정책만으로는 부족하다. 두 번째 방어 메커니즘이 **MFA(Multi-Factor Authentication, 다중 인증)** 다. AWS에서 필수는 아니지만 사용이 매우 권장된다.

사용자, 특히 관리자는 설정을 바꾸거나 리소스를 삭제하는 등 많은 작업을 할 수 있다. 그래서 최소한 **루트 계정과 모든 IAM 사용자**는 보호하고 싶을 것이다. 비밀번호 외에 어떻게 더 보호할까? 바로 MFA 장치다.

MFA는 **아는 것(비밀번호)** 과 **가진 것(보안 장치)** 을 조합한다.

```text
MFA = 아는 것(비밀번호) + 가진 것(보안 장치)
```

예를 들어 Alice는 비밀번호를 알고 있고 MFA 토큰을 생성하는 장치도 가지고 있다. 로그인할 때 이 둘을 함께 써야 성공한다.

```text
Alice
  -> 비밀번호를 알고 + MFA 토큰 장치를 소유
  -> 둘을 함께 입력해야 로그인 성공

효과
  -> 비밀번호가 도난·유출돼도
  -> 해커가 물리 장치까지 확보해야 하므로 계정 탈취가 훨씬 어렵다
```

여기까지가 이론이다. 이제 콘솔에서 비밀번호 정책을 편집하고 루트 계정에 MFA를 등록한다.

## 비밀번호 정책 설정

IAM 콘솔의 **계정 설정(Account settings)** 에서 비밀번호 정책을 편집한다.

```text
IAM 콘솔 > 계정 설정 > 비밀번호 정책
  -> IAM 기본 비밀번호 정책 사용
  -> 또는 사용자 지정으로 직접 구성
```

사용자 지정 시 위에서 본 옵션(최소 길이, 문자 유형 요구, 만료, 만료 시 처리, 재사용 방지)을 콘솔에서 바로 켜고 끌 수 있다.

## 루트 계정 MFA 설정

루트 사용자로 로그인한 상태에서 다음 경로로 들어간다.

```text
오른쪽 상단 계정 이름 > 보안 자격 증명(Security credentials)
  -> "내 보안 자격 증명 (루트 사용자)"
```

여기서 **MFA 장치 할당**을 진행한다.

```text
1) 장치 이름 지정        -> 예: MyiPhone (원하는 이름)
2) 장치 유형 선택        -> 인증 앱(가상) / 보안 키 / 하드웨어 TOTP 토큰
                            여기서는 가상이므로 "인증 앱" 선택
3) 호환 앱으로 QR 스캔   -> Android·iOS 호환 앱 목록 제공 (예: Twilio Authy)
                            앱에서 계정 추가 후 QR 코드 스캔
4) 연속 MFA 코드 2개 입력 -> 앱이 생성한 현재 코드와 다음 코드를 입력
                            (장치가 올바르게 설정됐는지 검증)
5) MFA 추가 클릭
```

QR 코드를 스캔하면 인증 앱이 시간에 따라 바뀌는 코드를 생성한다. AWS가 코드 두 개를 연속으로 요구하는 것은 장치가 제대로 연동됐는지 확인하기 위해서다.

루트 계정에는 최대 **8개**의 MFA 장치를 등록할 수 있고, 등록한 장치는 목록에서 확인하거나 **제거**할 수 있다.

> 주의: MFA 장치(휴대폰 등)를 분실하면 계정에서 락아웃될 수 있다. 장치를 안전하게 보관하고, 불안하면 등록 대신 흐름만 익혀 두는 편이 낫다.

## MFA 로그인

설정 후에는 로그아웃했다가 다시 로그인해 동작을 확인한다.

```text
로그인
  -> 계정/비밀번호 입력
  -> MFA 코드 입력 (인증 앱에 표시된 코드)
  -> 제출 -> 로그인 완료
```

비밀번호에 더해 MFA 코드까지 요구되므로 계정 보안이 한 단계 강화된다.

## 정리

```text
[이론]
계정 보호 = 비밀번호 정책 + MFA
비밀번호 정책 -> 최소 길이 / 문자 유형 / 변경 허용 / 만료(예 90일) / 재사용 방지
MFA          -> 아는 것(비밀번호) + 가진 것(장치), 비밀번호 유출돼도 장치 없이는 로그인 불가
MFA 장치     -> 가상(Google Authenticator·Authy) / U2F 키(YubiKey) / 키 팝(Gemalto) / GovCloud(SurePassID)

[설정]
비밀번호 정책 -> IAM 콘솔 > 계정 설정 > 비밀번호 정책
루트 MFA     -> 계정 이름 > 보안 자격 증명 > MFA 장치 할당
             인증 앱 선택 -> QR 스캔 -> 연속 코드 2개 -> 추가 (최대 8개)
MFA 로그인   -> 비밀번호 + MFA 코드
주의         -> MFA 장치 분실 시 락아웃 위험
```
